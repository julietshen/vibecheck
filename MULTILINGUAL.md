# Multilingual Evaluation — Open Safety Models across APAC Languages (2026-09-16)

> Generated by Claude (Claude Code, Opus 4.8) with Juliet Shen. All figures are produced
> by the harness in `apac-customization/` from model-generated outputs; verify before
> external use. Small, single-labeler samples — directional, not definitive.

How well do open safety models — off the shelf and customized — apply one plain-language
policy across APAC languages? This companion to `RESULTS.md` / `STEERABILITY.md` reports a
**models × languages matrix** on three harms in the languages where each has real data.
It supports the customization work in `apac-customization/` (policy-as-classifier,
LoRA fine-tuning, base-model choice).

## Setup

| | |
|---|---|
| **Metric** | F1 (positive = the harm), under one generic plain-language policy per harm |
| **Steerability** | % of flagged items released when the policy is rewritten to *permit* the harm (a policy-follower releases ~all; a fixed-prior model keeps flagging) |
| **Harms / data** | moneylending ads (synthetic SEA set, id/ms/th/tl/vi); fraud (ChiFraud, zh, CC BY-NC 4.0); offensive language (TB-OLID/HASOC, romanized Bengali, AGPL-3.0); gendered abuse (SWSR zh + Uli hi/ta/en, CC BY 4.0) |
| **Serving** | Shieldstral + Qwen local (MLX / Apple silicon); cope-b + gpt-oss-safeguard on Modal H100 |
| **Reproduce** | runners under `apac-customization/{demo1_shieldstral,rung2_lora,demo3_cope,demo4_safeguard,demo5_ideology}/` |

## Fine-tuning (LoRA) — where customization helps and where it doesn't

Same recipe (Qwen3-1.7B, rank 16, ~300 examples, ~90 s on an M4 Max), different harms:

| Fine-tune target | Base F1 | Tuned F1 | Effect |
|---|---|---|---|
| Moneylending, SEA (synthetic) | 0.857 | **1.000** | licensed-lender false positives 6/8 → 0/8 |
| Fraud, Chinese (ChiFraud, real) | 0.769 | **0.880** | false positives on normal finance text 40% → 5% |
| Offensive, Bengali (TB-OLID, real) | 0.643 | **0.308** ⚠ | recall collapsed 0.90 → 0.20 — made it worse |

Fine-tuning fixed the objective harms; on the subjective harm in the hardest language it
*hurt* — 270 examples taught a small model to under-flag. Fine-tuning is not a guaranteed fix.

Data: SWSR (zh) + Uli (hi/ta/en).

| Model | Overall F1 | Per-language recall (en / zh / hi / ta) |
|---|---|---|
| **Shieldstral-1.0-3B** | 0.574 (P 0.70 / R 0.49) | — (weaker than its moneylending 1.00) |
| **Qwen3-1.7B** (base) | 0.632 | en **20/20**, zh **18/20**, hi **9/20**, ta **7/20** |

The cliff reappears — this time on **Indic** languages: Qwen catches English and Chinese
gendered abuse but misses roughly two-thirds of Hindi and Tamil. Gendered abuse is also
harder for every model than moneylending because it is more **subjective** (Shieldstral drops
from 1.00 to 0.57). More models to be added; served models (cope-b/safeguard) not yet re-run.

## Key findings

1. **The failure is the language, not the model type.** cope-b is *both* 100% steerable and
   the best multilingual all-rounder. The robust failure is romanized / low-resource Bengali,
   where every model drops.
2. **"Multilingual" is non-uniform.** Shieldstral is best on SEA (1.00) and Chinese (0.946)
   yet worst on romanized Bengali (0.387). Test the exact languages you serve.
3. **Steerability ≠ language coverage** — they're independent axes; you can have one without
   the other, and no single open model has all of steerable + multilingual + auditable + cheap.
4. **Fine-tuning has limits** — it needs enough good labels; subjective, culturally-loaded
   harms in low-resource languages may need data collection, not a bigger adapter.

## Provenance and caveats

- Datasets: **ChiFraud** (Tang et al., COLING 2025, CC BY-NC 4.0); **TB-OLID / HASOC 2024**
  (AGPL-3.0); **SWSR** (Jiang et al., CC BY 4.0); **Uli** (Tattle, CC BY 4.0). The SEA
  moneylending set is **synthetic** and needs native-speaker validation (`apac-customization/data/NOTICE.md`).
- Small samples, single labeler, keyword/similarity selection bias — the general caveats in
  `README.md` apply. Synthetic-set scores demonstrate mechanism, not real-world accuracy.
- Served-model figures require the cope-b / safeguard Modal endpoints (see `serve_cope.py`,
  `serve_safeguard.py`); both were stopped after the runs.
